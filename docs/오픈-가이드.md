> 뼈대는 전부 만들어져 있습니다. 아래 순서대로 진행하면 **매일 11시에 인스타그램 캐러셀이 자동 발행**되고,

> 어려운 단계는 화면을 캡처해서 보내주시면 어디를 누를지 짚어드립니다.

## 현재 상태 (이미 완료 ✅)

- ✅ 자동 발행 파이프라인 (렌더 → 업로드 → 발행 → 기록 → 알림)
- ✅ 콘텐츠 관제실 대시보드 (pslab과 동일 구조)
- ✅ 7월 발행 스케줄 6건 + 캐러셀 2건 완성 (7/6 명함 용지, 7/9 스티커 컷팅)
- ✅ GitHub Actions 무인 발행 워크플로 (매일 11:00 KST)
- ✅ 중복 발행 방지(멱등성)·실패 알림·오류 화면 가드

## 이제 하실 일 (순서대로)

### 1단계. 브랜치 합치기 (5분)
`claude/sns-automation-system-qhd0ip` 브랜치를 **main으로 머지**합니다.
GitHub 저장소 → Pull requests → New → 해당 브랜치 선택 → Merge.
> 머지 전까지는 자동 발행 cron이 돌지 않습니다.

### 2단계. 대시보드 켜기 (2분)
저장소 Settings → **Pages** → Source를 **GitHub Actions**로 선택.
잠시 후 `https://leejiho-pslab.github.io/snsautomatic/` 에서 관제실이 열립니다.
> ⚠️ 무료 플랜은 **public 저장소만** Pages가 됩니다. private면 화면이 404로 나옵니다. (시크릿은 public이어도 노출되지 않아요)

### 3단계. 인스타그램 연결 (30~60분, 가장 중요)
동성인쇄소 인스타그램이 **프로페셔널 계정**이고 **Facebook 페이지에 연결**되어 있어야 합니다.
그다음 토큰 발급: `.claude/skills/sns-autopost/references/setup-guide.md` 1번 절차대로.
발급한 값을 저장소 Settings → Secrets and variables → **Actions**에 등록:

| 시크릿 이름 | 내용 |
|---|---|
| `META_ACCESS_TOKEN` | Meta 시스템 사용자 토큰 |
| `IG_USER_ID__DONGSUNG_PRINT` | 인스타그램 비즈니스 계정 ID |

### 4단계. 이미지 호스팅 연결 (10분)
https://cloudinary.com 무료 가입 → Dashboard의 `CLOUDINARY_URL` 복사 →
시크릿 `CLOUDINARY_URL` 등록. (인스타그램 API가 공개 이미지 주소를 요구해서 필요합니다)

### 5단계. 카카오톡 알림 연결 (15분, 선택이지만 추천)
setup-guide.md 3번 절차대로 발급 → 시크릿 `KAKAO_REST_KEY`, `KAKAO_REFRESH_TOKEN` 등록.
발행 성공/실패가 카카오톡 "나에게 보내기"로 옵니다. 미등록 시 알림만 조용히 생략됩니다.

### 6단계. 리허설 (5분)
로컬이면 `npm run doctor` — 토큰·계정·콘텐츠를 전부 점검해서 남은 일을 한국어로 알려줍니다.
(IG 계정 ID를 모를 때도 doctor가 후보를 찾아줍니다. 카카오 토큰 발급은 `node scripts/kakao-auth.js`)
GitHub에서는 Actions 탭 → **autopost** → Run workflow → mode에 `test` 입력 → 실행.
초록불이면: 렌더·업로드까지 전 과정이 실제로 통과된 것. 관제실 체크리스트가 5칸 중 4칸 채워집니다.

### 7단계. 실전 오픈
아무것도 안 해도 됩니다. 다음 스케줄 날짜 11:00에 첫 캐러셀이 자동 발행되고,
카카오톡 알림 + 관제실 "발행됨" 뱃지 + 게시물 링크로 확인됩니다.
바로 발행해보고 싶으면: Run workflow → mode `live`.

## 뭔가 이상할 때

- **발행이 안 된다** → ① 관제실에서 다음 예정일이 실제로 지났는지 ② Actions 탭에 빨간불이 있는지 ③ 체크리스트에 빈칸이 있는지 순서로 확인. 재실행해도 중복 발행은 안 됩니다(멱등).
- **대시보드가 안 뜬다** → 저장소가 private로 바뀌지 않았는지, Pages Source가 GitHub Actions인지 확인.
- **에러 코드가 보인다** → `.claude/skills/sns-autopost/references/troubleshooting.md` 표에서 코드 검색.
